## 二、重要提示：字符集问题已修复

**问题**：初次执行SQL时报错 `Data too long for column 'field_label'`

**原因**：MySQL客户端字符集为 `gbk`，数据库字符集为 `utf8mb4`，导致字符集转换错误

**解决方案**：使用 `--default-character-set=utf8mb4` 参数执行SQL

**后续建议**：
```bash
# 在 MySQL 配置文件（my.ini）中添加：
[mysql]
default-character-set=utf8mb4

[client]
default-character-set=utf8mb4
```

## 四、功能使用说明

### 4.1 配置生效机制

**前端缓存**：
- TTL 5分钟自动失效
- 保存/重置后立即清除缓存
- 下次打开表单时重新加载配置

**生效时机**：
- 配置保存后，**下次打开表单**时生效
- 已打开的表单不受影响（需关闭重开）

### 4.2 配置规则说明

**软约束 vs 硬约束**：
- **前端软约束**：字段配置只影响表单展示（红星、空值校验）
- **后端硬约束**：数据库非空约束、Service业务校验保持不变
- 即使用户绕过前端也能被后端挡住

### 4.3 默认必填字段

| 模块 | 必填字段 |
|---|---|
| 采购订单 | orderTime（创建时间）、supplierId（供应商） |
| 采购入库 | inTime（入库时间）、supplierId（供应商） |
| 采购退货 | returnMode（退货模式）、returnTime（退货时间）、supplierId（供应商） |
| 供应商 | name（供应商名称）、sort（排序） |

## 五、常见问题

### Q1: 配置保存后不生效？

**原因**：前端缓存未失效

**解决**：
1. 关闭当前表单弹窗
2. 等待5分钟（缓存自动失效）
3. 或清除浏览器缓存（Ctrl+F5）
4. 重新打开表单

### Q2: 菜单找不到"字段配置"？

**原因**：菜单缓存未刷新

**解决**：
1. 系统管理 → 菜单管理 → 刷新缓存
2. 退出重新登录
3. 或重启后端服务

### Q3: 配置后仍然提示必填？

**原因**：后端硬约束（数据库非空、Service校验）

**说明**：
- 字段配置只影响前端展示
- 后端硬约束不受影响
- 这是设计行为，保证数据安全

## 七、租户ID问题修复（2026-05-12 16:30）

**问题现象**：字段配置页面有4个Tab，但没有显示任何字段数据

**问题原因**：
- 数据库初始化脚本中的数据使用了 `tenant_id = 0`（默认租户）
- 但 admin 用户使用的是 `tenant_id = 1`
- MyBatis Plus 的多租户插件自动过滤了不同租户的数据，导致查询不到

**解决方案**：
```sql
UPDATE erp_field_config SET tenant_id = 1 WHERE tenant_id = 0;
```

**验证结果**：
- ✅ purchase_order（采购订单）：23 个字段
- ✅ purchase_in（采购入库）：34 个字段
- ✅ purchase_return（采购退货）：21 个字段
- ✅ supplier（供应商）：53 个字段

**重要提示**：
- 如果你的系统使用了其他租户ID，需要相应修改 `tenant_id` 的值
- 或者在初始化脚本中使用当前登录用户的租户ID
