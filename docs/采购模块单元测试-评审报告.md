## 四、测试设计要点

### 4.1 统一模板

```java
@InjectMocks private XxxServiceImpl service;
@Mock private XxxMapper xxxMapper;
@Mock private OtherDependency otherDependency;

@BeforeEach
public void setUp() {
    ReflectionTestUtils.setField(service, "noRedisDAO", new ErpNoRedisDAO() {
        @Override public String generate(String prefix) { return prefix + "20260520000001"; }
    });
}
```

### 4.2 关键技术决策

| 决策点 | 处理 |
|---|---|
| `noRedisDAO`（生成单号） | 用 `ReflectionTestUtils.setField` + 匿名子类覆盖 `generate(prefix)`，避免引入 Jedis-mock 依赖 |
| `@Lazy` 循环依赖字段 | 与普通 `@Resource` 一样标 `@Mock` 即可，Mockito 不区分 |
| `ArgumentCaptor` | 用于校验 insert/updateById 入参的具体字段（如赠品强制 0 价） |
| `AssertUtils.assertServiceException` | 直接传 `ErrorCode` 对象（非 `int` 错误码） |
| `BigDecimal` 比较 | 全部用 `compareTo == 0`，不用 `equals`（避开 scale 差异） |
| 凭证联动测试 | 用 `bookOpenService.isVoucherTypeEnabled` mock 控制开关 |
| 乐观锁失败 | mock `updateByIdAndStatus` 返回 0，验证抛 PROCESS_FAIL |

### 4.3 Mock 调用统计

| 文件 | @Mock 数量 | 关键 mock 行为 |
|---|---|---|
| Supplier | 1 | 仅 supplierMapper |
| PurchaseOrder | 5 | mapper×3 + supplierService + productService |
| PurchaseIn | 14 | + lazy purchaseOrderService + stockRecordService + warehouseService + adminUserApi + autoVoucherBuilder + voucherService + bookOpenService + voucher{,Item}Mapper |
| PurchaseReturn | 12 | 同上但少 warehouseService/adminUserApi/lazy voucherService |
| PriceAdjust | 7 | + lazy stockService（用于 adjustStockCostAmount）|

## 六、测试维护建议

### 6.1 保持稳定的 mock 桩

- `ErpNoRedisDAO.generate` 桩固定返回 `prefix + "20260520000001"` —— 永远不会因日期推进失败
- 所有 `ErpAuditStatusEnum.PROCESS.getStatus()` / `APPROVE.getStatus()` 直接用枚举，不硬编码 10/20

### 6.2 后续扩展应遵循

| 场景 | 做法 |
|---|---|
| 新增一个 status 流转分支 | 在对应 `updateXxxStatus` 测试组增加 case，复用 `prepareXxxDO()` 工厂方法（如有） |
| 新增校验规则 | 用 `assertServiceException(() -> service.xxx(req), ERROR_CODE)` 单测 |
| 新增产品扩展字段 | 不必加测试（VO ↔ DO 映射由 BeanUtils 处理） |
| 业务联动新增依赖 | 在 `@Mock` 区追加，构造方法零改动 |

### 6.3 失败诊断快速参考

如未来某个用例突发失败：

| 症状 | 排查 |
|---|---|
| `BadSqlGrammarException` | 检查 mock 是否漏 stub `selectListByXxx` 等返回 |
| `NullPointerException @ stockService` | 检查 lazy 依赖是否漏注入（`@Mock private ErpStockService stockService`） |
| `BigDecimal not equal` | 用 `compareTo == 0` 替换 `equals`（scale 差异） |
| `ServiceException 错误码不匹配` | 比对 `ErrorCodeConstants` 的具体常量，不要硬编码 int |
