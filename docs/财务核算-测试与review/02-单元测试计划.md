# 财务核算模块单元测试计划

> 计划时间：2026-05-20
> 测试范围：`yudao-module-erp` 财务核算模块全栈（Service + Controller + Mapper + VO）
> 测试基类：`BaseDbUnitTest`（H2 + Jedis-mock，集成测试）+ `BaseMockitoUnitTest`（纯 Mock 单元测试）
> 测试框架：JUnit 5 + Mockito + Spring TestContext + AssertJ + RandomUtils（Podam）

## 一、整体目标

| 维度 | 目标 |
|---|---|
| 覆盖率 | Service 层行覆盖率 ≥ 80%，分支覆盖率 ≥ 70% |
| 测试用例数 | 约 500 个（每个 Service ~20-40 个，每个 Controller ~10-20 个） |
| 测试文件数 | 28 个（17 Service Test + 11 Controller Test） |
| 关键算法 | 借贷平衡 / 凭证号月度重置 / 自动凭证 / 状态机 / 反审删凭证 等 100% 覆盖 |
| 跨模块联动 | 业务单据审核 ↔ 凭证生成 ↔ 反审删凭证（端到端） |
| 验证 Bug | 验证 Code Review 发现的 17 个严重问题在测试中能被复现 |

## 二、测试基类选型

| 测试场景 | 基类 | 适用情况 |
|---|---|---|
| 纯算法 / 纯逻辑（借贷平衡校验、凭证号格式、金额计算） | `BaseMockitoUnitTest` | 不依赖数据库，所有 Mapper Mock |
| 涉及多 Mapper 联动（CRUD + 子表 diff） | `BaseDbUnitTest` | H2 真实建表，验证 SQL |
| Controller 接口（参数校验 + 权限 + 响应） | `BaseDbUnitTest` + `MockMvc` | 完整 Spring 容器 |
| 凭证生成（涉及 Redis 凭证号 + 多 Service 协作） | `BaseDbUnitTest` + Jedis-mock | H2 + 内存 Redis |

## 六、模拟数据策略

| 场景 | 策略 |
|---|---|
| DO 随机数据 | `RandomUtils.randomPojo(ErpVoucherDO.class, o -> { ... })` 局部覆盖 |
| 主子表关联 | 子表显式 `setVoucherId(voucher.getId())` |
| 用户上下文 | `try-with-resources` 包裹 `SecurityFrameworkUtils.setLoginUser(...)` |
| 多租户 | 测试基类已配置 `tenant_id=1`（参考 ErpSaleConfigServiceImplTest） |
| 时间 | 用 `LocalDate.of(2026, 5, 15)` 等固定日期，不要用 `LocalDate.now()` |
| 金额 | 用 `new BigDecimal("100.00")` 显式精度 |
| Redis | `Jedis-mock` 自动启用，`generate` / `generateMonthly` 方法直接调用 |

## 七、断言策略

| 类别 | 工具 |
|---|---|
| 业务异常 | `AssertUtils.assertServiceException(() -> ..., ERROR_CODE)` |
| DO 字段比较 | `AssertUtils.assertPojoEquals(expected, actual, "createTime", "updateTime")`（忽略时间戳） |
| 集合大小 | `assertThat(list).hasSize(N)` |
| BigDecimal | `assertThat(value).isEqualByComparingTo("100.00")` 而非 `equals` |
| 状态机 | `assertThat(after.getAuditStatus()).isEqualTo(APPROVE.getStatus())` |
| Mapper 调用次数 | `verify(voucherMapper, times(N)).insert(any())` |

## 十、风险与遗留项

### 风险

1. **H2 数据库与 MySQL 8 行为差异**：例如 `last("limit 1")` 在 H2 可能不支持。
2. **Jedis-mock 不完全模拟 Redis 持久化**：凭证号月度重置测试可能受影响。
3. **多租户上下文**：测试 DO 的 tenant_id 必须显式设为 1，否则被多租户拦截器过滤。
4. **业务单据外键依赖**：测试凭证生成时需要先建采购入库 / 销售出库 DO，依赖链长。

### 不在测试范围

| 项 | 原因 |
|---|---|
| 三大报表 formula 取数 | 当前是骨架页，formula 为空 |
| 月末结转 / 期间损益结转 | 客户暂缓 |
| VoucherType 11 银行转账凭证 | 资金模块未搭建 |
| 前端 Vue 组件交互 | 不在 Java 单元测试范围 |
| 性能压测 | 单元测试只验证基线 SQL 次数 |
