## 6. 测试技术沉淀

### 6.1 Java 21 + mockito-inline + ErpNoRedisDAO 不可 Mock 问题

**症状**：`ErpNoRedisDAO` 通过 `@Resource` 注入 `RedissonClient`，Mockito 在 Java 21 下无法直接 mock final 内部类。

**解决方案**（已在 5 个 Service 测试中复用）：

```java
private final AtomicReference<String> nextNoRef = new AtomicReference<>("XXX-DEFAULT");

@BeforeEach
void setupNoRedisDAO() {
    ReflectionTestUtils.setField(service, "noRedisDAO", new ErpNoRedisDAO() {
        @Override public String generate(String prefix) { return nextNoRef.get(); }
        @Override public String generateMonthly(String prefix) { return nextNoRef.get(); }
    });
}
```

测试方法只需 `nextNoRef.set("OTHER-202605-000001")` 控制返回值。

### 6.2 SecurityFrameworkUtils.getLoginUserId() 静态方法 Mock

```java
try (MockedStatic<SecurityFrameworkUtils> mocked = mockStatic(SecurityFrameworkUtils.class)) {
    mocked.when(SecurityFrameworkUtils::getLoginUserId).thenReturn(123L);
    // ... 测试代码
}
```

### 6.3 Controller 测试模式（不走 MockMvc）

```java
class ErpXxxControllerTest extends BaseMockitoUnitTest {
    @InjectMocks private ErpXxxController controller;
    @Mock private ErpXxxService service;
    
    @Test void testCreate() {
        when(service.createXxx(any())).thenReturn(123L);
        CommonResult<Long> result = controller.create(reqVO);
        assertEquals(0, result.getCode());
        assertEquals(123L, result.getData());
        verify(service).createXxx(reqVO);
    }
}
```

直接调用 Controller 方法，避免 Spring MVC 容器启动开销，单类执行 < 100ms。

### 6.4 ArgumentCaptor 校验 DO 字段

凭证生成等场景需校验最终入库的 DO 字段值：

```java
ArgumentCaptor<ErpVoucherDO> captor = ArgumentCaptor.forClass(ErpVoucherDO.class);
verify(voucherMapper).insert(captor.capture());
assertEquals("记-202605-000001", captor.getValue().getVoucherNo());
assertEquals(new BigDecimal("100.00"), captor.getValue().getTotalDebitAmount());
```
